Pràctica 5: Regulació Proporcional-Integral (PI)

Controlador PI continu — Estudi de com l'acció integral elimina l'error permanent (offset)

1 Enunciat de l'activitat

L'objectiu d'aquesta Pràctica 5 és estudiar el comportament i la gran utilitat de la regulació Proporcional-Integral (PI) continu per eliminar l'error permanent.

En la pràctica anterior vam constatar que un regulador proporcional pur (P pur) té la limitació física d'assegurar l'estabilitat però generant un error permanent (offset). En aquesta activitat introduirem progressivament l'acció integral (T_i). Observarem com la integració de l'error al llarg del temps força la variable del procés a convergir exactament al valor desitjat (Setpoint), alhora que analitzarem com una acció integral massa agressiva (un valor de T_i molt petit) provoca oscil·lacions i sobrepicos (overshoots) elevats.

2 Fonaments Teòrics de la Regulació PI i l'Acció Integral

El regulador PI combina el control proporcional (que reacciona instantàniament a l'error actual) amb l'acció integral, que acumula els errors passats en el temps:

// Equació del regulador PI paral·lel o ideal
u(t) = K_p_c · e(t) + (K_p_c / T_i) · ∫ e(τ) dτ
// On:
• e(t) = r(t) - y(t) (Error instantani)
• K_p_c : Guany proporcional del controlador
• T_i : Constant de temps integral (en segons)
• ∫ e(τ) dτ : Integral acumulada de l'error des de t=0

• Implementació de l'Algorisme PI en JavaScript (Codi)

En sistemes encastats, autòmats (PLCs) o simulacions en temps real, l'equació contínua es discretitza mitjançant el mètode d'Euler. A continuació es mostra un exemple didàctic en JavaScript:

// Variables globals que guarden l'estat històric del bucle
let integralError = 0.0; // Acumulador de l'error integral
// Funció executada periòdicament cada 'dt' segons
function calcularControlPI(consigna, temperatura, Kpc, Ti, dt, uMax, integralActiva) {"{"}
const error = consigna - temperatura;
// 1. Acció Proporcional (P)
const pTerm = Kpc * error;
// 2. Acció Integral (I) - Suma d'Euler
if (integralActiva && Ti > 0) {"{"}
integralError += error * dt;
{"}"} else {"{"}
integralError = 0.0;
{"}"}
const iTerm = (integralActiva && Ti > 0) ? (Kpc / Ti) * integralError : 0.0;
// 3. Esforç ideal combinat
const uIdeal = pTerm + iTerm;
// 4. Limitació física (Saturació de l'actuador entre 0V i uMax)
const uSaturada = Math.max(0.0, Math.min(uMax, uIdeal));
// 5. Algorisme Anti-windup (Desaturació de la integral)
if (uIdeal !== uSaturada && integralActiva && Ti > 0) {"{"}
// Si s'ha saturat i l'error té el byte del mateix signe, desfem l'acumulació
if (Math.sign(error) === Math.sign(uIdeal)) {"{"}
integralError -= error * dt;
{"}"}
{"}"}
return uSaturada;
{"}"}

• Com s'elimina l'error permanent?

L'acció integral calcula l'àrea total sota la corba de l'error. Vegem com canvia la dinàmica del sistema:

  1. Mentre hi hagi una diferència entre la consigna i la temperatura (és a dir, e(t) ≠ 0), l'acció integral anirà incrementant de manera progressiva l'esforç de control (u(t)).
  2. Fins i tot si l'error es fa molt petit, el terme integral acumulat reté el valor històric per continuar alimentant l'actuador (per exemple, mantenint un corrent mínim a l'escalfador del forn).
  3. D'aquesta manera, a diferència de l'acció Proporcional, l'esforç de control pot ser superior a zero (u > 0) encara que l'error s'anul·li del tot (e = 0).
  4. En règim permanent estacionari, la sortida s'ajustarà perfectament a la consigna: l'error permanent esdevé zero (e_offset = 0.000 V).

• L'Efecte de T_i i el Risc de Saturation (Saturació i Windup)

La constant de temps integral T_i es troba al denominador de l'equació:

Acció Integral = ( K_p_c / T_i ) · ∫ e(t) dt
  • T_i alt (∞ o gran): L'acció integral és molt lenta i feble. L'offset s'elimina molt a poc a poc.
  • T_i baix (petit): L'acció integral s'intensifica i acumula ràpidament. Això fa que el sistema sigui més ràpid, pero acumula massa empenta, provocant un gran sobrepico (overshoot) i un temps d'estabilització llarg amb oscil·lacions.
  • Anti-windup actiu: En el nostre simulador, per evitar que l'acumulador creixi indefinidament quan l'actuador es satura al seu límit físic (U_max), s'ha integrat un algorisme de desaturació condicional (Anti-windup) que suspèn la integració quan l'actuador està saturat.

3 Guia de Treball Pas a Pas

Pas 1: Activació de l'Acció Integral i eliminació de l'offset

Configureu la planta de primer ordre pura (K_p = 2.0, τ_1 = 3.0 s, inèrcies τ_2 = τ_3 = 0 s, retard θ = 0 s). Activeu el PID Continu, amb consigna r = 2.0 V i guany K_p_c = 1.0.
Inicialment amb T_i = ∞, observeu l'error d'uns 0.67 Volts. Després, activeu l'acció Integral i ajusteu T_i = 10.0 s. Observeu com, amb molta suavitat, la corba taronja de la temperatura s'acosta i s'estabilitza exactament sobre la consigna verda de 2.0 V. Comproveu que l'offset de règim estacionari es redueix a 0.000 V.

Pas 2: Reducció de T_i i aparició del sobrepico (Overshoot)

Amb la mateixa planta de primer ordre i mantenint el guany K_p_c = 1.0, aneu disminuint el valor de T_i. Proveu amb T_i = 5.0 s, 3.0 s, i finalment 1.5 s. Observeu que la pujada és més ràpida, però la temperatura es passa de llarg de la consigna abans d'estabilitzar-se. Consulteu el valor de "Sobrepico Màxim" al panell de rendiment i completeu la taula de dades de l'informe.

Pas 3: Combinació inèrcia/retard + acció integral forta

Introduïu retard i inèrcies reals: poseu τ_2 = 1.0 s i retard θ = 1.0 s. Deixeu K_p_c = 2.0 i activeu una acció integral molt forta posant T_i = 2.0 s. Observeu com la combinació de retards i una integració agressiva provoca grans oscil·lacions que triguen molt a esmorteir-se o que fins i tot fan que el sistema esdevingui completament inestable (oscil·lacions perpètues).
